# Modding and the modlist — S.T.A.L.K.E.R. G.A.M.M.A.

Sources for this page: the GAMMA repository at commit
`ab0f743af42a3b3b0b0ee853b3676f5189f7f0d0` — `G.A.M.M.A/modpack_data/modlist.txt`,
`modpack_maker_list.txt`, the 385 folders under `G.A.M.M.A/modpack_addons`, the 239 shipped
`mod_system_*.ltx` patch files, `G.A.M.M.A/modpack_patches/`, `README.md`, `Patchnotes.md` —
plus the official wiki pages **Installing-GAMMA** and **Technical-Support-FAQ** (backups,
moving an install, updating).

GAMMA is a **modular platform**, not a frozen game. The README's own framing: "the main
motivation behind this project is to provide an easy to install, automatically updated and
modular modding platform for Stalker Anomaly." The community says it too — the Steam
"Rookie's Guide" line is the same idea: *"GAMMA is meant to be modular and customizable …
You're supposed to enable/disable/change things to get the experience you WANT."*

That cuts both ways: you can change almost anything, and almost anything you change can be
the cause of your next crash.

---

## 1. What the launcher actually produces

```
GAMMA/                              <- the "GAMMA folder" you created
├── .Grok's Modpack Installer/      <- G.A.M.M.A. Launcher.exe lives here
├── mods/                           <- every addon, one folder each (the MO2 data dir)
├── modlist.txt                     <- load order + enabled/disabled state (MO2-owned)
├── profiles/
│   └── G.A.M.M.A/                  <- default profile: modlist.txt, plugins.txt, settings
├── downloads/                      <- the archives the launcher downloaded
├── overwrite/                      <- loose files MO2 could not attribute to a mod
└── ModOrganizer.exe / ModOrganizer.ini
Anomaly/                            <- a *separate* folder on the same drive
├── AnomalyLauncher.exe, bin/, db/, gamedata/ (vanilla-ish)
└── appdata/user.ltx, appdata/savedgames/, appdata/logs/
```

MO2 gives the game a **virtual file system**: nothing is copied into `Anomaly/`. Instead,
MO2 assembles a merged `gamedata/` at launch from the enabled mods in load order. That is
why (a) an addon can be enabled/disabled instantly and (b) antivirus products that block
MO2's virtualization break the install.

## 2. Reading `modlist.txt`

`modlist.txt` is generated by MO2 (`# This file was automatically generated by Mod
Organizer.`) and uses one line per mod:

| Prefix | Meaning |
|---|---|
| `+` | enabled |
| `-` | disabled |

The **first** mod line in a fresh GAMMA list is `+G.A.M.M.A. End of List_separator`, and the
very first line is `-End`. MO2's `-End` marker means *"stop here: do not manage loose files
in the game directory"* — so anything listed after the End of List separator is either
deliberately parked or is a "disabled by default" container:

- **`G.A.M.M.A. Disabled (DO NOT ACTIVATE)_separator`** — a whole block of addons that are
  shipped but must stay off (conflicting variants, DX9 variants, abandoned patches, mods
  whose upstream is unmaintained).
- **`G.A.M.M.A. End of List_separator`** — end of the managed list; **optional** addons live
  after it (for example *Dynamic Aspect Ratio Tweaks* for ultrawide, which the FAQ tells you
  to enable there).

Grouping is done with separator entries whose names end in `_separator`, so the MO2 list
reads like a table of contents. Separators present in GAMMA's shipped list include (not
exhaustively): `G.A.M.M.A. Audio_separator`, `G.A.M.M.A. Combat and Balance_separator`,
`G.A.M.M.A. Economy and Craft_separator`, `G.A.M.M.A. Fixes_separator`,
`G.A.M.M.A. HUD_separator`, `Realistic Magazines_separator`,
`Alternative Addons & Patches_separator`, plus the `Disabled` and `End of List` markers
above.

## 3. Addon naming conventions in `mods/`

| Pattern | What it is |
|---|---|
| `G.A.M.M.A. <thing>` | GAMMA's **own** addon (written or heavily rewritten by the pack). Examples: `G.A.M.M.A. Economy (don't disable, turn on Black Market to buy gear)`, `G.A.M.M.A. Actor Damage Balancer`, `G.A.M.M.A. Mutants Overhaul`, `G.A.M.M.A. Upgrades Overhaul`, `G.A.M.M.A. Difficulty Presets Rebalance`, `G.A.M.M.A. Artefacts Reinvention`, `G.A.M.M.A. Tutorials` |
| `NNN- <mod> - <author>` | a **third-party** addon, numbered in the launcher's list (e.g. `197- New Storylines (DLTX minimodpack) - Demonized`, `140- Weapon Parts Overhaul - arti`, `234- Dynamic Anomalies Overhaul - Demonized`) |
| `<name> - <author>` | an unnumbered third-party addon |
| `*_separator` | MO2 grouping marker, not a mod |
| `Pre-0.9… Saves Fix`, `Fix for saves made before 10-10-22` | compatibility shims that convert old saves |

The numbering matters for a completely different reason: the README's credits section says
**"For numbered addons (105-), original authors must be contacted before repost and
modifications."** GAMMA's own un-numbered additions are free to edit, adapt and repost *as
long as the source (addon author, "from Stalker GAMMA") is indicated*. Don't strip credits.

## 4. Where an addon's content lives

Every addon folder mirrors the game's data layout:

```
<addon>/gamedata/configs/…       .ltx and .xml configs
<addon>/gamedata/scripts/…       .script (Lua, X-Ray dialect)
<addon>/gamedata/textures|meshes|sounds|anims|levels|particles/…
<addon>/meta.ini                 MO2 metadata (name, version, source URL, category)
```

MO2 shows the source link in `meta.ini`; in the MO2 UI you can right-click an addon and
**visit moddb.com** to see its original page (the README highlights this: "each addon
original source … is directly accessible from the Mod Organizer 2 instance by right-clicking
addons > visit moddb.com").

The repository also ships the pack's **data tables** at the top level of
`modpack_addons/` — useful when you want to check a number rather than guess:

| File | Content |
|---|---|
| `gamma_ammo_weapon_table.xlsx` | ammo damage/penetration table, gun power, per-rouble efficiency |
| `artefacts_values.xlsx` | artefact protection values by tier (the `+ … ++++++` / `- … ------` grid) |
| `toolkits_chance.xlsx` | which toolkit tier drops where (expressed as the per-map tool lists + computed chances) |
| `good_weapons.txt` | the curated list of guns by class and NATO/WP affiliation |
| `to_mipmap.txt` | texture pipeline helper list |

These are the pack's working spreadsheets — treat them as strong evidence but not as
gospel: a value can be superseded by a later `mod_system_*.ltx`, and the game is final.

## 5. Configs and DLTX (how GAMMA edits other mods)

GAMMA ships modded executables with **DLTX** support and uses it everywhere. The conventions
you will see in the files:

- A patch file named `mod_system_<something>.ltx` in `gamedata/configs/` **overrides
  sections of configs loaded by other mods** without replacing them. There are **239** such
  files across the shipped addons (plus 5 in `modpack_patches`). Examples:
  `mod_system_GAMMA_repair_kits_uses.ltx` (sets `max_uses = 3` on the four toolkits),
  `mod_system_grok_plates_rework.ltx` (armor-plate absorption values),
  `mod_system_zzzzzzzz_repair_kits_rename.ltx` (renames the cleaning/repair kits shown as
  Type A/B/C/D).
- Inside a patch, a section header written `![section_name]` **edits** the existing section,
  and `![section_name]:parent_section` **inherits** from a parent section and then edits or
  extends it — the pattern used for almost every item in
  `mod_system_zzzzzzzzzzzzzzzzz_grok_artifacts.ltx` (`![af_itcher]:af_base`).
- The engine side of this is visible in `modpack_patches/gamedata/scripts/`:
  `options_modded_exes_logging.script` exposes an option `print_dltx_warnings` and
  `options_modded_exes_optimizations.script` exposes `dltx_use_cache`; `lua_help_ex.script`
  documents `dltx_print`, `dltx_get_section`, `dltx_is_override`, `dltx_get_filename_of_line`.
  In other words: **DLTX is a first-class part of the pack, and there is a debug option to
  print override warnings when a patch does not match anything.**
- Load-order-ish prefixing is a real technique in this repo: files are deliberately named
  with runs of `z` (`mod_system_zzzzzzzzzzzzzzzzz_grok_artifacts.ltx`,
  `mod_system_zzzzzz_gamma_armor_protections.ltx`, `zz_item_artefact.script`) so they apply
  **after** everything that sorts earlier in the same directory. When your own patch is
  ignored, this is almost always why.

## 6. Adding your own addon (safe procedure)

1. **Copy the default profile first** — MO2 profile dropdown → *Manage…* → copy `G.A.M.M.A.`
   to e.g. `My Mods`, then select it. Never edit the shipped profile. (Same rule as the
   official backup instructions.)
2. Put the addon in `GAMMA/mods/<name>/` with a proper `gamedata/` inside, or install an
   archive through MO2 (which will complain about the "fomod"/layout if it is not
   MO2-shaped — fix the top-level folder first).
3. Enable it in MO2 and **place it where it belongs in the list** (see §7).
4. Launch and test on a **throwaway save** if the addon touches scripts, spawns, quests or
   save data. Addons that add or remove *items/sections* used in saves are the ones that
   corrupt saves.
5. Record what you changed and why (the pack's own way of doing this: README patch notes,
   one bullet per change).

### What is safe vs risky

| Change | Risk |
|---|---|
| Retextures, sounds, icons, HUD/menu visuals | Low |
| Config value tweaks via `mod_system_*` overlays (prices, weights, caps) | Low–medium (balance/save-data impacts) |
| Adding new items, ammo types, artefacts, magazines | Medium (saves reference section names) |
| Scripts that touch task, spawn, save or quest logic | High |
| Removing/renaming existing sections, engines/exe swaps, DX variants | Highest — capable of irrecoverably breaking saves |

## 7. Load order: how to think about it

MO2 resolves conflicts by **which mod wins per file** (and, within a file, DLTX by section).
Practical rules:

1. **Later mod wins the file.** Your patch must sit *below* the mod it patches; GAMMA's own
   patches use `mod_system_z*` names to sit late within a directory.
2. **Full-file replacements beat patches.** If a later mod ships a whole `w_ak74.ltx`, it
   replaces the earlier one entirely and any DLTX edit made by an earlier mod against the
   original file is lost. GAMMA's answer is to make GAMMA's edits themselves DLTX overlays so
   they compose — do the same.
3. **Separators are not mods.** Enabling/disabling them only changes the list's readability.
4. **"Disabled (DO NOT ACTIVATE)" is not a suggestion.** Those files are shipped because they
   are known-broken in combination with the current pack.
5. When in doubt: change **one** mod, then test.

## 8. Version control and contributing upstream

- The GAMMA repository is developed on **`dev2`**; the README's contributing section says:
  **"Any Pull Request should be made to the dev2 branch. Anyone can contribute to this
  project."** `main` receives merges (the snapshot commit here is
  `Merge pull request #740 from Grokitach/dev2`).
- Bug reports and support live on the official Discord (https://discord.gg/stalker-gamma),
  where the `#how-to-install` channel is the authoritative install source.
- The published mod list with authors and source links is available at
  **https://stalker-gamma.com/api/list**; the repository's own copy is
  `G.A.M.M.A/modpack_data/modpack_maker_list.txt` — 473 source URLs across 492 lines, grouped
  by category headings such as *Audio, Visual, Animations, Gameplay, Stashes, Gunplay*.
  The ModDB downloads are registered under the GAMMA ModDB page (mod id 222467 in the
  list's first entry), which is why "visit moddb.com" from MO2 lands on real addon pages.
- Because GAMMA redistributes almost nothing third-party, **updating an addon means
  re-downloading it from ModDB/GitHub** — and the FAQ warns not to chase ModDB status
  updates (see `references/installation-setup.md` §6).

## 9. Commonly-tweaked GAMMA systems (where to look)

| Want to change | Look at |
|---|---|
| Difficulty presets and all their multipliers | `G.A.M.M.A. Difficulty Presets Rebalance/gamedata/configs/plugins/difficulty.ltx` — `[econ_1..3]` (Tourist/Scavenger/Survivalist) and `[gdiff_1..3]` (Easy/Medium/Hard); details in `references/keybinds-settings.md` |
| Everything MCM exposes | `G.A.M.M.A. MCM values - Rename to keep your personal changes/gamedata/configs/axr_options.ltx` — `[mcm]` section (per-mod options) and `[options]` section (engine/A-Life options such as `alife/event/emission_frequency`) |
| Population, squad sizes, mutant enable/disable | the **ZCP (Zone Customization Project)** addon — see its own `FAQs.txt`, which documents squad-size multipliers, variance, disabled-mutant replacement, and the "Not enough IDs" engine limit |
| Trader stock, prices, supply tiers | `G.A.M.M.A. Economy …/gamedata/configs/items/trade/presets/gamma_wp_preset.ltx` and `gamma_nato_preset.ltx` (`[supply_1_…]` …), `…/items/settings/part_prices.ltx`, `mod_system_weapons_gamma_attachments_price.ltx` |
| Artefact tiers, spawn groups, costs | `G.A.M.M.A. Artefacts Reinvention/…/items/settings/artefacts.ltx` (group definitions per anomaly field) and `mod_system_zzzzzzzzzzzzzzzzz_grok_artifacts.ltx` (per-artefact stats) |
| Recipes (crafting/cooking/repair) | `G.A.M.M.A. Artefacts Reinvention/…/items/settings/craft.ltx`, `mod_system_grok_recipes.ltx`, plus the Economy addon's `mod_system_GAMMA_items_repair_quantity.ltx` |
| Weapon/armor balance | `G.A.M.M.A. Outfits Balances/…/tools/armor_values.tsv` + `ballist_res_sections.tsv` (source tables), `G.A.M.M.A. Actor Damage Balancer/…/mod_system_items_armors_br_class_rework.ltx`, `G.A.M.M.A. Armors Balancing/…/mod_system_zzzzzz_gamma_armor_protections.ltx` |

All of these are **files in the user's own install** — when a question is about *their*
numbers, read their file, not this page.

## 10. Things that look like modding advice but are traps

- **Don't** copy files into `Anomaly/gamedata/` by hand. MO2 owns that; loose files bypass
  load order and are the classic source of "my mod does nothing" *and* "my game broke".
- **Don't** edit `Anomaly/appdata/user.ltx` while the game is running; it is rewritten on
  exit.
- **Don't** enable an addon from the "Disabled (DO NOT ACTIVATE)" block "just to try it".
- **Don't** mix DX8/9 addons into a DX11 list (and vice versa) — use the dedicated DX8/9
  modlist project.
- **Don't** assume a mod is compatible because it is installed; the pack ships several
  *alternative* addons for the same slot under "Alternative Addons & Patches".
- **Don't** stack two mods that both rewrite weapon jam logic, magazine logic or the
  detector UI. GAMMA's own README warns about "Mags Redux (Disable G.A.M.M.A. Unjam
  Reload)" vs the default unjam-on-reload-key setup — the two are mutually exclusive
  designs, which is exactly why the addon names say so.
